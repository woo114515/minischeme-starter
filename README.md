# mini-Scheme 解释器挑战

## 1. 任务目标与考察内容

**任务**：vibe coding，把 `src/` 里的骨架补全为一个符合 `spec.md` 的 mini-Scheme 解释器，让全部验收测试通过。预计 30 分钟。你不需要会编程——你负责向 AI 描述需求、验证结果、报错时继续迭代。

考察三项：

1. **功能正确**：解释器能否通过全部验收测试（底线）。
2. **模块化**：代码按骨架划分的文件组织，每个文件只做一件事，不把所有代码堆进一个文件。
3. **代码规范**：例如合适的注释，是否有足够的鲁棒性。

## 2. Scheme 语言简介与模块化思路

### Scheme 是什么

mini-Scheme 是一种极简的编程语言：几乎一切都写成 `(操作符 参数...)` 的形式——操作符写在最前面，括号决定运算顺序。例如 `(+ 1 2)` 表示 1 加 2。完整的语法规则见 `spec.md`（面向零基础编写，§1 语序必读）。

### 一个解释器怎么运转

解释器就是"读懂一段程序文本，算出结果，再打印出来"的程序。流水线只有三步：

```
程序文本 ──读──→ 表达式 ──算──→ 值 ──打印──→ 结果
```

**模块化**就是把这条流水线拆成职责单一的小模块（`src/` 里的各个 `.py` 文件）：读的归读的、算的归算的、打印的归打印的。这样每一步都能独立验证——测试挂了，你能立刻知道问题出在哪一步，也知道该让 AI 改哪个文件。

## 3. Autograder 使用方法

评分器 `autograder.pyz` 已经放在本仓库根目录。在仓库根目录运行：

```
python3 autograder.pyz python3 src/main.py
```

- 它会运行 12 组验收用例，每组是一段 mini-Scheme 程序，逐字节比对输出。
- `PASS` 表示通过；`FAIL` 会显示你的解释器的报错信息，或"输出不符"加上你的实际输出——**不会给出期望输出**，请对照 spec 判断哪里不对。
- 只跑一组：`python3 autograder.pyz python3 src/main.py --case=006`。
- 用例难度递增。**别一次冲全部**：先让第一组通过，再逐步推进。
- 测试通过 ≠ 结束：用 spec 里的例子自己写几段程序跑一跑，确认你能讲清楚每个输出为什么对。
